# PR 봇 리뷰 처리 규칙

> `.claude/local/` 하위. 이그노어 대상이라 레포에 안 올라간다.
> PR을 올리면 봇이 코드 리뷰를 남긴다. 리뷰 내용을 붙여넣으면 아래 순서로 처리한다.

---

## 처리 순서

1. **각 리뷰를 수용할지 반박할지 판단한다. 무조건 수용 금지.**
   봇이 틀렸거나, 맥락을 모르고 지적했거나, 이미 의도적으로 그렇게 짠 경우가 있다.
2. **파일 단위로 리뷰를 종합한다.** 같은 파일에 여러 리뷰가 붙으면 묶는다.
3. **브리핑을 먼저 제공한다. 수정은 지시를 받고 시작한다.**
   브리핑 단계에서 바로 코드를 고치지 않는다.

---

## 브리핑 형식

파일마다 이 순서를 지킨다.

| 순서 | 내용 |
| --- | --- |
| 1 | 그 파일이 가진 맥락·배경 설명 |
| 2 | 어떤 리뷰가 들어왔는지 — **비전공자도 이해할 수 있게 풀어서** 요약 |
| 3 | 그에 대한 판단과 근거 |
| 4 | 결론 |

마지막에 전체 판단을 표로 요약한다.

| 항목 | 판단 | 이유 |
| --- | --- | --- |
| (지적 내용) | 수용 / 반박 / 유지 | (한 줄 근거) |

---

## 추가 규칙

- 봇끼리 지적이 충돌하면 그 사실을 브리핑에 명시한다.
- 여러 파일에 걸친 리뷰는 주된 파일에 넣고 나머지에서 교차 언급한다.
- **반박할 때는 근거를 실측으로 제시한다.** 빌드 산출물 확인, 런타임 실측값(브라우저 계산 스타일, 네이티브 로그, 실기기 동작), 실제 응답 헤더 등.
  소스만 보고 판단한 봇의 오탐이 실제로 있었다.
- 봇이 지적하지 않았지만 **같은 문제가 있는 다른 파일**을 발견하면 함께 보고한다.
- 반영/미반영 근거는 커밋 메시지에도 남긴다. 재리뷰에서 같은 지적이 올라올 때 답변 근거가 된다.

---

## 왜 이렇게 하나

봇 리뷰를 그대로 반영하면 의도적으로 짠 코드가 뒤집힌다.
용어를 그대로 옮기면 받는 쪽이 판단할 수 없다.

**판단 주체는 사람이고, AI는 판단 재료를 만드는 역할이다.**

### 다른 프로젝트 사례 (참고)

Next.js + Tailwind v4 웹 프로젝트에서 나온 판정이다. 사실 관계가 아니라 "어떤 근거로 반박했는지"의 기준점으로만 본다.

| 지적 | 판단 | 근거 |
| --- | --- | --- |
| IME 조합 중 Enter 처리 | **수용** | 한글 마지막 글자 확정 시 키보드가 닫히는 실제 버그. 봇이 지적하지 않은 2곳도 함께 수정 |
| 정적 `og:url` 제거 | **수용** | 일부 메신저가 `og:url`을 클릭 목적지로 써서 공유 링크가 홈으로 갈 위험 |
| `calc()` 연산자 공백 누락 | **반박** | 빌드 산출물 확인 결과 Tailwind v4가 공백을 자동 삽입. 소스만 본 오탐 |
| 문서 날짜가 미래 | **반박** | 작성일이 맞음. 리뷰 기준일이 UTC로 계산된 것 |
| 클립보드 자동 복사 제거 | **유지** | Android는 사용자 활성화가 5초 유효해 안전 범위. 제거하면 고치려던 문제가 되돌아옴 |
